## Архитектура

```
Harbor/
├── client/          # React + Vite фронтенд (IndexedDB для данных)
├── server/          # Express + tRPC бэкенд (MySQL опционально)
├── drizzle/         # Схема базы данных и миграции
├── shared/          # Общие типы и константы
├── dist/            # Сборка (после pnpm build)
├── .env             # Переменные для локальной разработки
├── .env.docker      # Переменные для Docker
└── docker-compose.yml
```

**Хранение данных:**
- Фронтенд хранит все данные (комнаты, активы, бронирования) в **IndexedDB браузера** — без необходимости сервера.
- MySQL используется только если вы хотите серверную синхронизацию. Без него бэкенд возвращает пустые списки, а фронтенд работает автономно.

## Требования

| Компонент | Версия |
|-----------|--------|
| Node.js | `>=20.19` или `>=22.12` |
| pnpm | `10.4.1` |
| MySQL | `8.0+` *(опционально)* |
| Docker | `20.10+` *(для Docker-запуска)* |
| Docker Compose | `2.0+` *(для Docker-запуска)* |

Проверить версии:
```bash
node --version    # должно быть v20.19+ или v22.12+
pnpm --version    # должно быть 10.4.1
```

Установить pnpm если не установлен:
```bash
npm install -g pnpm@10.4.1
```

## Локальный запуск

### Шаг 1 — Клонируйте проект и перейдите в папку

```bash
git clone <url-репозитория> Harbor
cd Harbor
```

### Шаг 2 — Создайте файл окружения

```bash
cp .env.docker.example .env
```

Откройте `.env` и проверьте:
- `JWT_SECRET` — любая случайная строка (обязательно для production, для dev можно оставить дефолт)
- `DATABASE_URL` — строка подключения к MySQL. **Если MySQL нет — оставьте пустым**, приложение работает без него

```env
JWT_SECRET=my-local-dev-secret-change-me
DATABASE_URL=mysql://roomassets:roomassets_password@localhost:3306/roomassets
# Или оставьте пустым если MySQL не нужен:
# DATABASE_URL=
```

### Шаг 3 — Установите зависимости

```bash
pnpm install
```

При первой установке pnpm спросит разрешение на сборку нативных пакетов (`esbuild`, `@tailwindcss/oxide`). Разрешите все:
```bash
pnpm approve-builds
# Нажмите 'a' чтобы выбрать всё, затем Enter
```

### Шаг 4 — Запустите в режиме разработки

```bash
pnpm dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

> **Примечание:** В терминале появится предупреждение `[OAuth] ERROR: OAUTH_SERVER_URL is not configured!` — это **нормально**. OAuth отключён по умолчанию, приложение работает без авторизации.

## Docker Compose

Самый простой способ запустить с MySQL — через Docker Compose.

### Шаг 1 — Создайте файл окружения для Docker

```bash
cp .env.docker.example .env.docker
```

Откройте `.env.docker`:
```env
# Обязательно замените на свой секрет
JWT_SECRET=your-strong-random-secret-here

# Эти данные совпадают с параметрами сервиса db в docker-compose.yml
DATABASE_URL=mysql://roomassets:roomassets_password@db:3306/roomassets
```

Сгенерировать сильный секрет:
```bash
openssl rand -hex 32
```

### Шаг 2 — Соберите образ

```bash
docker-compose build
```

Первая сборка занимает 3–5 минут (скачивается Node.js, устанавливаются зависимости).

### Шаг 3 — Запустите сервисы

```bash
docker-compose up -d
```

Docker запустит два контейнера:
- `roomassets-db` — MySQL 8.0 на порту 3306
- `roomassets-backend` — приложение на порту 3000

### Шаг 4 — Примените миграции базы данных

Только при **первом** запуске:
```bash
docker-compose exec backend pnpm db:push
```

Эта команда создаст таблицы `rooms`, `assets`, `bookings`, `users` в MySQL.

### Шаг 5 — Откройте приложение

Перейдите на [http://localhost:3000](http://localhost:3000)

### Управление контейнерами

```bash
# Посмотреть статус
docker-compose ps

# Логи приложения
docker-compose logs -f backend

# Логи базы данных
docker-compose logs -f db

# Остановить
docker-compose down

# Остановить и удалить данные (ОСТОРОЖНО — удалит данные MySQL!)
docker-compose down -v

# Перезапустить после изменений кода
docker-compose build && docker-compose up -d
```

## Production сборка

Если хотите собрать и запустить вручную без Docker:

### Сборка

```bash
pnpm build
```

Эта команда:
1. Запускает `vite build` — собирает React-приложение в `dist/public/`
2. Запускает `esbuild` — собирает Node.js сервер в `dist/index.js`

### Запуск

```bash
# Установите переменные и запустите
NODE_ENV=production \
  JWT_SECRET=your-secret \
  DATABASE_URL=mysql://user:pass@host:3306/dbname \
  PORT=3000 \
  node dist/index.js
```

Или через `.env` файл (dotenv подхватывается автоматически):
```bash
NODE_ENV=production node dist/index.js
```

## Переменные окружения

| Переменная | Обязательна | Описание |
|------------|-------------|---------|
| `JWT_SECRET` | Да | Секрет для подписи сессионных cookie. Минимум 32 символа |
| `DATABASE_URL` | Нет | Строка подключения к MySQL. Без неё — данные не сохраняются на сервере |
| `PORT` | Нет | Порт сервера. По умолчанию `3000` |
| `NODE_ENV` | Нет | `development` или `production`. Влияет на сборку Vite и логи |
| `VITE_APP_ID` | Нет | ID приложения в Manus OAuth. Не нужен без Manus |
| `OAUTH_SERVER_URL` | Нет | URL OAuth-сервера. Не нужен без Manus |
| `VITE_OAUTH_PORTAL_URL` | Нет | URL портала OAuth. Не нужен без Manus |
| `OWNER_OPEN_ID` | Нет | OpenID владельца (Manus) |
| `OWNER_NAME` | Нет | Имя владельца (Manus) |
| `BUILT_IN_FORGE_API_URL` | Нет | URL Manus Forge API (для AI-функций) |
| `BUILT_IN_FORGE_API_KEY` | Нет | Ключ Manus Forge API |

> **Минимальный рабочий `.env`:**
> ```env
> JWT_SECRET=any-random-string-at-least-32-chars
> ```

## База данных

### Создать базу вручную (без Docker)

```sql
CREATE DATABASE roomassets CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'roomassets'@'localhost' IDENTIFIED BY 'roomassets_password';
GRANT ALL PRIVILEGES ON roomassets.* TO 'roomassets'@'localhost';
FLUSH PRIVILEGES;
```

### Применить миграции

```bash
pnpm db:push
```

Команда запускает `drizzle-kit generate && drizzle-kit migrate` — создаёт таблицы из файлов в `drizzle/`.

### Структура таблиц

| Таблица | Описание |
|---------|---------|
| `rooms` | Комнаты: id, name, capacity, features |
| `assets` | Активы: id, name, inventoryCode, status |
| `bookings` | Бронирования: resourceType, resourceId, title, start, end, notes |
| `users` | Пользователи (только при включённом OAuth) |

### Загрузить тестовые данные

В папке `seed/` есть файлы с примерами:
- `seed.example.json` — шаблон структуры
- `sample-data.json` — готовые тестовые данные

Импортируйте через вкладку **Данные → Импорт** в интерфейсе приложения.

### Резервная копия

```bash
# Создать бэкап
docker-compose exec db mysqldump -u roomassets -proomassets_password roomassets > backup_$(date +%Y%m%d).sql

# Восстановить из бэкапа
docker-compose exec -T db mysql -u roomassets -proomassets_password roomassets < backup_20240101.sql
```

## Что было исправлено

Проект поставлялся с четырьмя критическими проблемами. Все они исправлены:

### 1. Конфликт двух систем хранения данных
**Проблема:** `Home.tsx` читал данные через tRPC → MySQL, а `AppContext` писал в IndexedDB. Два слоя не синхронизировались.

**Исправление:** `Home.tsx` переведён на `useApp()` из `AppContext`. Единственный источник данных — IndexedDB браузера. MySQL используется опционально только через серверную часть при наличии `DATABASE_URL`.

### 2. Мутации требовали авторизации без OAuth
**Проблема:** `rooms.create`, `assets.create`, `bookings.create` и все update/delete были `protectedProcedure` — требовали валидную сессию через Manus OAuth. Без настроенного OAuth любая запись возвращала `UNAUTHORIZED`.

**Исправление:** Все мутации переведены на `publicProcedure`. Серверный слой доступен без авторизации.

### 3. Отсутствовал `.env.docker.example`
**Проблема:** В `DOCKER.md` написано `cp .env.docker.example .env.docker`, но файл не существовал.

**Исправление:** Файлы `.env.docker.example` и `.env` созданы с подробными комментариями.

### 4. `vite.config.ts` заточен под Manus
**Проблема:** `allowedHosts` содержал только домены `*.manus.computer`. На любом другом домене Vite блокировал запросы в dev-режиме.

**Исправление:** `allowedHosts: true` — принимает любой хост. Также убраны Manus-специфичные плагины (`vite-plugin-manus-runtime`, `@builder.io/vite-plugin-jsx-loc`).

### 5. TypeScript ошибка
**Проблема:** `storageProxy.ts` содержал ошибку типизации `req.params[0]`.

**Исправление:** Приведение типа `(req.params as Record<string, string>)[0]`. TypeScript теперь компилируется без ошибок.

### 6. Лишний analytics-скрипт в `index.html`
**Проблема:** `index.html` содержал `<script src="%VITE_ANALYTICS_ENDPOINT%/umami">` с незаполненными env-переменными. Vite выдавал предупреждения при сборке.

**Исправление:** Скрипт удалён. Сборка проходит без предупреждений.

## Устранение проблем

### `pnpm install` зависает или падает

```bash
# Очистите кэш
pnpm store prune

# Попробуйте без frozen lockfile
pnpm install --no-frozen-lockfile
```

### Предупреждение про `approve-builds`

```
Ignored build scripts: @tailwindcss/oxide, esbuild, msw
```

Запустите:
```bash
pnpm approve-builds
# Нажмите 'a' для выбора всех, затем Enter
```

### `[OAuth] ERROR: OAUTH_SERVER_URL is not configured!`

Это **нормальное** предупреждение при работе без Manus OAuth. Приложение работает в штатном режиме. Если хотите убрать — добавьте в `.env`:
```env
OAUTH_SERVER_URL=https://your-oauth-server.example.com
```

### Ошибка подключения к MySQL

```
Error: connect ECONNREFUSED 127.0.0.1:3306
```

Варианты:
1. MySQL не запущен — запустите или уберите `DATABASE_URL` из `.env` (приложение работает без БД)
2. Неправильные credentials — проверьте строку подключения
3. База не создана — выполните `CREATE DATABASE roomassets;`

### Порт 3000 занят

Измените порт в `.env`:
```env
PORT=8080
```

Или найдите и завершите процесс:
```bash
# macOS / Linux
lsof -i :3000
kill -9 <PID>

# Windows
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

### Docker: контейнер backend не запускается

```bash
# Посмотреть причину
docker-compose logs backend

# Проверить что db запущен и healthy
docker-compose ps db

# Пересобрать образ
docker-compose build --no-cache
docker-compose up -d
```

### Данные пропали после перезагрузки браузера

Данные хранятся в IndexedDB конкретного браузера и профиля. Они **не синхронизируются** между устройствами и браузерами. Для резервной копии используйте вкладку **Данные → Экспорт** в интерфейсе.
